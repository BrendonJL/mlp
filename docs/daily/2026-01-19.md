## Session Focus

## PPO v5 Configuration Refinements

After multiple failed v5 attempts on Jan 18, found and adapted parameters from vietnh1009's successful Super Mario Bros PPO implementation.

### Key Changes from Failed v5 Attempts

| Parameter | Previous v5 | New v5 (vietnh1009-based) | Rationale |
|-----------|-------------|---------------------------|-----------|
| action_space | SIMPLE_MOVEMENT | **RIGHT_ONLY** | Simpler action space, agent can't go left |
| learning_rate | 0.00015 | **0.0001** | Matches successful implementation |
| gamma | 0.99 | **0.9** | Shorter horizon, faster credit assignment |
| n_steps | 2048 | **512** | Smaller rollout buffer |
| batch_size | 64 | **16** | Tiny batches, more frequent updates |
| ent_coef | 0.1 | **0.01** | Much lower entropy (was overcorrecting) |
| gae_lambda | 0.95 | **1.0** | No GAE smoothing (Monte Carlo returns) |
| total_timesteps | 10M | **5M** | vietnh1009's training length |

### SpeedrunRewardWrapper Adjustments

With RIGHT_ONLY action space, backward movement is now involuntary (physics/knockback only), so:
- `backward_penalty=0.0` - disabled (can't penalize involuntary movement)
- `base_reward_scale=0.1` - scale down base game rewards to match shaping magnitude
- All rewards scaled down 10x for value function stability

```python
# Current SpeedrunRewardWrapper parameters
forward_bonus=0.1      # Scaled down 10x
backward_penalty=0.0   # Disabled for RIGHT_ONLY
idle_penalty=0.02      # Low penalty
death_penalty=5.0      # Scaled down 10x
completion_bonus=100.0 # Scaled down 10x
base_reward_scale=0.1  # Scale base game rewards
```

## Major Discovery: Agent Reaching Level End!

### Database Analysis Reveals Progress

Queried the database and found the agent is consistently reaching the end of the level:

```sql
SELECT MAX(distance_traveled) as max_dist FROM episodes
WHERE experiment_id = (SELECT MAX(experiment_id) FROM experiments);
-- Result: max_dist = 3156 pixels!
```

Multiple episodes reaching x=3154 (the stairs before the flagpole):

| Episode | Distance | Reward | Time Remaining |
|---------|----------|--------|----------------|
| 2052 | 3156 | 1079 | 281 |
| 799 | 3154 | 750 | 279 |
| 736 | 3154 | 750 | 284 |
| 1622 | 3154 | 886 | 307 |

**Key observation:** Agent arrives with 280+ seconds remaining - time is NOT the issue!

### The Reward/Distance Mystery

Terminal output shows episodes with `mile=141.5` (ALL milestones hit, including 3154) but database shows much lower `distance_traveled`:

```
✅ Logged episode 2243: reward=1399.4, distance=897
   💰 base=573.6, fwd=594.5, back=0.0, idle=-0.2, death=-10.0, mile=141.5
```

**The puzzle:** How can `mile=141.5` (x_pos reached 3154+) but `distance_traveled=897`?

### Investigation Findings

1. **Milestones track max x_pos reached during episode**
2. **distance_traveled logs x_pos at episode END**
3. **With RIGHT_ONLY, agent can't go backward intentionally**

Checked `life` values for these episodes:
```sql
SELECT episode_number, distance_traveled, life FROM episodes WHERE episode_number BETWEEN 2243 AND 2248;
-- All show life=255 (uint8 overflow/special state)
```

`life=255` appears in many episodes (not just end-of-level), suggesting a gym-super-mario-bros quirk with episode termination reporting.

### Theories

1. **Level completion detection bug**: Agent IS completing the level, but `flag_get` isn't being set properly during the victory animation
2. **x_pos reporting quirk**: When Mario interacts with the flagpole/end area, x_pos reports a weird value
3. **Death at flagpole**: Agent reaches stairs, can't figure out the final jump to grab flag, dies somehow

**Resolution:** Will run visual evaluation after training completes to see exactly what happens at the end.

### Linting/Type Errors Resolved

Fixed all Pyright and ruff errors across the codebase. Main issues were `gym` vs `gymnasium` type stub incompatibilities:

| File | Issues Fixed |
|------|--------------|
| `src/environments/wrappers.py` | `gym.ObservationWrapper` not exported, `FrameStackWrapper.reset()` bug, tuple unpacking |
| `src/training/train.py` | `TransposeWrapper` not assignable to `GymEnv` |
| `src/environments/vec_mario_env.py` | Same `TransposeWrapper` type issue, import sorting |
| `scripts/evaluate_model.py` | Unused `_states` variable |
| `scripts/test_explore_env.py` | Tuple unpacking for `reset()`, `action_space.n` attribute |

**Key learnings:**
- `gym` library lacks proper type stubs for `ObservationWrapper`, `Wrapper`
- Use `# type: ignore[misc]` for class inheritance from untyped gym classes
- Use `# type: ignore[arg-type]` when passing gym wrappers to SB3 (type systems don't know they're compatible)
- Bare `_` is the universal "throwaway" variable (not `_states`)
- `assert x is not None` preferred over type ignore when you can guarantee runtime value
