# 2026-01-23 - Phase 5: PPO v6 Development & v5 Post-Mortem

## Session Focus
Analyzed v5 failure, created v6 config combining v4's foundation with v5's clip scheduler, observed entropy collapse mid-training, adjusted ent_coef for second attempt.

## PPO v5 Post-Mortem

### Evaluation Results - FAILURE
Ran visual evaluation of the final v5 model:
- **Avg Distance:** 556 pixels (worse than random baseline!)
- **Max Distance:** 898 pixels
- **Success Rate:** 0%

This was shocking given terminal logs during training showed `mile=141.5` (full milestones) frequently.

### Database Analysis Revealed the Truth

Queried the actual training data (experiment_id=52, 7,430 episodes):

| Milestone | Episodes Reached | Percentage |
|-----------|------------------|------------|
| 650px | 6,936 | 93.4% |
| 900px | 5,992 | 80.6% |
| 1200px | 3,802 | 51.2% |
| 2000px | 1,184 | 16% |
| 3000px | 26 | 0.35% |
| 3154px | 24 | 0.32% |

**Only 24 episodes (0.3%) actually reached the end of the level** - not the hundreds suggested by terminal output.

### Critical Finding: Negative Reward/Distance Correlation
```
Correlation between distance and reward: -0.174
```

**Higher distances = LOWER rewards.** The SpeedrunRewardWrapper created completely backwards incentives. This explains why the final policy was so bad - it learned that going further was punished.

### v5 Failure Summary
- ❌ SpeedrunRewardWrapper created negative correlation
- ❌ RIGHT_ONLY action space too restrictive
- ❌ Terminal logging was misleading (showing wrong milestone totals)
- ❌ Policy degraded - early training reached further than final policy

## PPO v6 Design

### Philosophy: v4 Foundation + Selective v5 Improvements

**Kept from v4 (worked well):**
- SIMPLE_MOVEMENT action space
- Standard RewardShapingWrapper
- gamma=0.99 (longer horizon)
- gae_lambda=0.95 (advantage smoothing)
- batch_size=128, n_steps=1024
- 10M timesteps

**Added from v5:**
- Clip range scheduler: 0.15 → 0.05 (adaptive clipping)
- Slightly higher learning rate: 0.00005 (vs v4's 0.00003)

### v6 Attempt #1 Results (Killed at 31%)

Ran for ~8 hours, reached 3.1M / 10M timesteps (~7,100 episodes).

**Performance:**
- Distance: ~2007 pixels consistently
- Reward: ~4000 avg

**Problem: Entropy Collapse**
| Metric | Early (2%) | At 31% |
|--------|------------|--------|
| entropy_loss | -1.13 | -0.0799 |

Entropy dropped 14x! Agent became deterministic, stuck at ~2007 pixel barrier. For comparison, v4 reached 2725 pixels - v6 was 700 pixels behind.

**Decision:** Killed the run, not worth waiting 14 more hours for likely failure.

### v6 Attempt #2 Configuration

Increased entropy coefficient to encourage more exploration:

```yaml
ent_coef: 0.03  # Increased from 0.02
```

All other parameters unchanged. Training restarted.

## Technical Learnings

### Terminal Logging vs Database Reality
The SpeedrunRewardWrapper's `reward_breakdown` info dict was showing incorrect milestone totals in terminal output. Always verify with database queries - terminal logs can lie!

### Entropy Collapse Patterns
- **Healthy entropy:** -1.0 to -1.5 range
- **Warning signs:** Below -0.5
- **Collapse:** Approaching 0 (deterministic policy)

v6 attempt #1 went from -1.13 → -0.08 over 31% of training. This is faster collapse than we want.

### ent_coef Tuning
- 0.01 (v5): Too low, policy collapsed quickly
- 0.02 (v4/v6-attempt1): Still collapsed at ~30% training
- 0.03 (v6-attempt2): Testing now
