# 2026-01-18 - Phase 5: PPO v5 Deep Debugging & Reward Engineering

## Session Focus
Deep analysis of PPO v5 (SpeedrunRewardWrapper) failures, reward engineering debugging, and systematic hyperparameter tuning.

## Major Problem: Total Custom Reward Shaping Failures

### Experiment 39 - Initial SpeedrunRewardWrapper Run
Ran PPO v5 with `SpeedrunRewardWrapper` which **completely replaced** base game rewards with custom shaping.

**The Oscillation Exploit Discovery:**
Analysis script revealed episodes with **massive rewards for tiny distances**:
- Episode 4473: distance=176, reward=7,469 (42.44 reward/pixel!)
- Episode 203: distance=143, reward=7,114 (49.75 reward/pixel!)

**Root Cause:** Forward bonus (+1.0/pixel) vs backward penalty (-0.4/pixel) created an arbitrage:
```
Move right 100 pixels: +100 reward
Move left 100 pixels:  -40 reward
Net: +60 reward for a round trip, staying in place!
```

The agent learned to oscillate back and forth to farm infinite reward without progressing.

### Attempted Fixes and Failures

**Fix Attempt 1: Increase backward penalty to -1.2**
- Made oscillation unprofitable: net -20 per round trip
- Result: Agent still oscillated but now got punished for it
- Issue: Agent became stuck at ~480 pixels, learned "learned helplessness" - found oscillation was less bad than dying from pushing forward

**Fix Attempt 2: Re-add base game rewards**
- Changed from `reward = 0.0` to keeping base reward
- Result: High rewards for low distances due to base game + shaping stacking

**Fix Attempt 3: Scale down all shaping parameters**
- Cut forward/backward/idle penalties in half (0.5, 0.6, 0.5)
- Reduced death penalty from 200 to 50
- Scaled down milestones
- Result: Better correlation between distance and reward, but still unstable

**Fix Attempt 4: Entropy coefficient increase**
- Policy collapsed to deterministic behavior (distance=434, same reward repeatedly)
- entropy_loss crashed from -0.176 to -0.025 (near-zero exploration)
- Increased ent_coef from 0.02 to 0.1
- Reduced learning rate from 0.00025 to 0.00015

**Bug Discovery: Clip Range Scheduler Never Applied!**
Found bug in `train.py` line 153:
```python
# BUG: Used hyperparams["clip_range"] instead of clip_range variable
clip_range=hyperparams["clip_range"],  # Wrong!
clip_range=clip_range,                  # Correct!
```
The clip range annealing was set up but never passed to the model!

## Technical Learnings

### Reward Engineering Pitfalls

1. **Asymmetric penalties create exploits**: If forward_bonus > backward_penalty, oscillation becomes profitable.

2. **Removing base game rewards loses valuable signal**: Coins act as breadcrumbs, enemy kills teach engagement strategies. Pure movement reward says WHAT is good but not HOW to achieve it.

3. **Reward magnitude matters for value function stability**: Large reward values (1.0 per pixel vs 0.1) can destabilize the value function, causing high value_loss.

4. **Negative rewards can cause "learned helplessness"**: If pushing forward always leads to death (-200), the agent may prefer slow bleeding from oscillation over the "certain death" of progress.

### Policy Collapse Indicators

| Metric | Healthy | Collapse Warning |
|--------|---------|------------------|
| entropy_loss | < -0.5 | > -0.1 (near zero) |
| approx_kl | < 0.03 | > 0.1 |
| Same distance/reward repeated | Varied | Exact same values |

### PPO Research Paper Techniques

Read "Enhanced Proximal Policy Optimization for Complex Game AI" which suggested:
- **Adaptive clipping**: Clip range annealing from 0.2 → 0.05 (implemented)
- **Dual-clip objectives**: Prevents large negative policy changes (not implemented - requires SB3 subclassing)
- **Experience replay**: Unusual for on-policy PPO (not implemented)
- **GAE**: Already enabled with gae_lambda=0.95

## Key Insights

### Why Clear Incentives Aren't Enough
"Going right = good" doesn't teach "jump over the pit" or "stomp the enemy." The agent needs:
- Dense feedback (coins as breadcrumbs)
- Interaction rewards (enemy kills show engagement is possible)
- Domain knowledge encoded in rewards

### Local Minima in RL
The agent found oscillation was "less bad" than:
- Pushing forward and dying immediately (-200)
- Standing still and bleeding idle penalty

It's risk-averse based on experience, even when the "risky" option (pushing forward) would yield better total reward.
