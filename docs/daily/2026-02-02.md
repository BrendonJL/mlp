## The 2760 Ceiling Analysis

Investigated whether v7's ceiling was a tracking artifact or real:

```sql
-- Suspiciously low distances (would indicate stage 2 deaths from completions)
 experiment_name | sus_low_dist | early_deaths | total | sus_pct
-----------------+--------------+--------------+-------+---------
 ppo_v7_world1-1 |          103 |          117 | 16571 |    0.62
 ppo_v4_world1-1 |          661 |          919 | 18958 |    3.49
```

**Conclusion:** The ceiling is REAL, not a tracking artifact. If v7 was completing during training and having x_pos reset to stage 2, we'd see MORE low-distance episodes, not fewer.

## Phase 6 Planning: BC Pre-Training Research

### Key Findings from Research

| Source | Details |
|--------|---------|
| [smbdataset](https://github.com/rafaelcp/smbdataset) | 737k frames @ 60fps, 280 episodes, **has RAM in PNG metadata!** |
| [DAGGER Paper (CMU)](https://www.ri.cmu.edu/pub_files/2011/4/Ross-AISTATS11-NoRegret.pdf) | Tested on Mario, found BC gets "stuck" - DAGGER fixes via iterative labeling |
| TAS files (.fm2) | Frame-perfect inputs, but precision may not transfer with frame skip |

### The Frame Skip Problem

Both smbdataset and TAS files are recorded at 60fps (every frame). Our agent uses skip=4 (sees every 4th frame). This creates a fundamental mismatch:

- **Without validation:** BC might teach broken behavior if subsampled actions don't work
- **Our v4/v7 success used skip=4:** Removing it would slow training 4x

### Proof of Concept Plan (Before Full BC Implementation)

**Goal:** Validate that subsampled (every 4th frame) demonstration data can still complete level 1-1.

#### Test Design

```
Original Demo (60fps):    [A₁, A₂, A₃, A₄, A₅, A₆, A₇, A₈, ...]
Subsampled (skip=4):      [A₁, -----, -----, -----, A₅, -----, -----, -----, ...]
                                 ↓
                          Replay through env with skip=4
                                 ↓
                          Does Mario still complete the level?
```

#### Tasks

| Step | Task | Est. Time |
|------|------|-----------|
| 1 | Download smbdataset level 1-1 winning episodes | 30 min |
| 2 | Find/download TAS .fm2 file for world 1-1 | 15 min |
| 3 | Write smbdataset action parser (PNG metadata → actions) | 1 hour |
| 4 | Write TAS .fm2 parser (text → actions) | 1 hour |
| 5 | Map both to SIMPLE_MOVEMENT (256/buttons → 7 actions) | 30 min |
| 6 | Write replay test script (subsample + step through env) | 1 hour |
| 7 | Run tests, record distance/completion | 30 min |

**Total: ~4-5 hours**

#### Expected Outcomes

| Result | Interpretation | Next Step |
|--------|----------------|-----------|
| Completes level | Frame skip compatible! | Proceed with BC pre-training |
| Gets 80%+ through | Mostly works | BC viable, PPO will fix errors |
| Fails badly (<50%) | Timing too critical | Need different approach (remove skip or DAGGER) |

#### Predictions

- **smbdataset (human play):** Likely works - humans aren't frame-perfect
- **TAS (frame-perfect):** Basic sections work, tricks may fail - but 1-1 has few tricks

### Action Space Mapping Challenge

Both data sources use 256 NES button combinations. We need to map to our 7 SIMPLE_MOVEMENT actions:

```
SIMPLE_MOVEMENT = [
    ['NOOP'],           # 0
    ['right'],          # 1
    ['right', 'A'],     # 2 (right + jump)
    ['right', 'B'],     # 3 (right + run)
    ['right', 'A', 'B'], # 4 (right + jump + run)
    ['A'],              # 5 (jump)
    ['left'],           # 6
]
```

**Problem:** "left + A" (jump left) is NOT in SIMPLE_MOVEMENT but may appear in demos.
