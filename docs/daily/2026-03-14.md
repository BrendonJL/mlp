### Key Insights

`★ Insight ─────────────────────────────────────`
Docker layer caching works top-to-bottom: each instruction is a cached layer. If a layer changes, everything below it rebuilds. Always copy dependency files (`pyproject.toml`, `poetry.lock`) before copying source code — source code changes frequently, dependencies rarely. This keeps the slow `poetry install` step cached.
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
Git LFS doesn't store binary content in the git object database — it stores a tiny pointer file (a few hundred bytes). The actual content lives on an LFS server. This is why GitHub's 100MB limit doesn't apply to LFS objects: git history stays small regardless of file size.
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
Marksman and markdownlint are two separate tools solving different problems: markdownlint checks formatting rules (blank lines, heading styles, code fence syntax), while marksman is an LSP that provides go-to-definition and completions for markdown links. They have completely separate config files and can be tuned independently.
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
`nbstripout` registers itself as a git filter: `git config filter.nbstripout.clean "path/to/nbstripout"`. When Poetry recreates the venv, the path changes, so the filter silently fails. The fix is to re-run `nbstripout --install` after every venv recreation — or remove it if notebooks aren't being committed anyway.
`─────────────────────────────────────────────────`
